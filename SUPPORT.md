# FlowerKit Support

Use the channel that best matches your request so it can be handled efficiently.

## Documentation

Start with the [README](./README.md) and the
[API reference](./docs/index.md). The API reference includes the public types,
parameters, return values, errors, and usage examples for every kit.

## Usage Questions

Use [GitHub Discussions](https://github.com/yuri-moskvin/flowerkit/discussions)
for integration questions, API usage, SSR guidance, and ideas that are not yet
concrete feature requests. Discussions allow answers to remain searchable for
other users.

When asking for help, include:

- The FlowerKit version and import path
- The browser or Node.js version and whether SSR is involved
- The framework and bundler, when relevant
- A minimal code example
- The complete error message and relevant stack trace
- What you expected to happen

## Bug Reports and Feature Requests

Use [GitHub Issues](https://github.com/yuri-moskvin/flowerkit/issues) for
reproducible defects and scoped feature requests. Search for an existing issue
before opening a new one.

Feature requests are more actionable when they describe the recurring consumer
problem, proposed behavior, alternatives considered, and browser or SSR
requirements. Large or breaking proposals should be discussed before an
implementation is submitted.

## Security Reports

Do not report suspected vulnerabilities publicly. Follow the private reporting
instructions in [SECURITY.md](./SECURITY.md).

## Support Scope

FlowerKit is maintained on a best-effort basis. Support covers the public API of
supported package versions. Project-specific debugging, private application
code, and third-party framework or bundler configuration may require a minimal
reproduction before they can be investigated.

For contribution setup and pull request requirements, see
[CONTRIBUTING.md](./CONTRIBUTING.md).
